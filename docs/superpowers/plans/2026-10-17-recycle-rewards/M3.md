## Rules every M3 task follows

1. **Race test shape.** Each concurrent pair is covered in both orders: one case named `<A> then <B>`, one case named `<B> then <A>`, plus a `Promise.all` case where the pair is symmetric. A case that asserts an order ("B waits for A", "the second sees the first's write") forces it with `raceWithHold` or `holdFirstCall` from `race/fixtures/waste-fixtures.ts` (registry 4.10 forced interleaving): `raceWithHold(prisma, lockSql, first, second)` holds `lockSql` (a tagged `Prisma.sql` row `SELECT ... FOR UPDATE`) from a side transaction and checks `lockWaiters` itself, so use it only when both contenders really queue on that lock; with `holdFirstCall(obj, method)` the case does `await h.reached`, starts B with a settled flag, `await waitUntil(async () => bSettled || (await blockedBackends(prisma)) >= 1, 'B queued behind A')`, then `h.release()` and finally `h.restore()`. Never a `sleep`, never "start B N ms later". `barrierOnFirstCalls` (`race/helpers.ts`) is allowed only for "all N pre-checks read before any write". Import only the helper names a spec uses from `./fixtures/waste-fixtures` and declare none of them locally (TS2440 under ts-jest). Every race case asserts that no rejection message contains `40P01` or `P2034` (`expect(summarize(results).errors.join()).not.toMatch(/40P01|P2034/)`).
2. **Race module pattern.** `Test.createTestingModule({ imports: [PrismaModule], providers: [...] })`; real `SystemConfigService`, `RewardPointsService`, `WasteConfigService`, `WasteAccessService`, `WasteHoldService`, the M3 service under test; `{ provide: WasteNotifierService, useValue: <jest.fn per method resolving undefined> }`, `{ provide: NotificationsService, useValue: { notify: async () => undefined } }`, and `{ provide: WasteShipLockService, useValue: { evaluateAndLock: jest.fn().mockResolvedValue({ locked: false, shipLockedAt: null, cancelledRequestIds: [] }) } }`. If Nest reports a missing provider, add the class named in the error (or a `useValue` stub if it only sends messages). Never edit an M2 service to make a race spec pass. Fixtures come only from `race/fixtures/waste-fixtures.ts` and `race/helpers.ts` (registry 4.10). `afterAll`: `cleanupWaste(prisma, reg)` BEFORE `deleteItData(prisma, { userIds })`, then `moduleRef.close()`. `beforeAll`: `warmPool(prisma)`, `setConfig(prisma, 'waste.enabled', true)`, `setConfig(prisma, 'loyalty.point_expire_months', 12)`, all written before the first service call. **Saved config** (registry 4.10: a waste race spec restores every config row it changes): before the first `setConfig`, `beforeAll` saves the rows: `const CONFIG_KEYS = [<every key this spec passes to setConfig, in beforeAll or in a case>]; savedConfig = await prisma.systemConfig.findMany({ where: { key: { in: CONFIG_KEYS } } });`; `afterAll` restores them after `deleteItData` and before `moduleRef.close()`: `await prisma.systemConfig.deleteMany({ where: { key: { in: CONFIG_KEYS.filter((k) => !savedConfig.some((c) => c.key === k)) } } }); for (const c of savedConfig) await setConfig(prisma, c.key, c.value as never);` (precedent `race/referral-guest-referrer.race-spec.ts:86, 109-110`). **Config cache** (registry 4.10): `SystemConfigService` caches each key for 60 s per instance (`api/modules/system-config/system-config.service.ts:39`), so every `setConfig` that runs after the module compiled (inside a case, or in its `finally`) is followed by `(moduleRef.get(SystemConfigService) as unknown as { cache: Map<string, unknown> }).cache.clear();` (precedent `race/pf6-spin-prize-guard.race-spec.ts:49`); restore the original value in `finally` and clear again. Never call `SystemConfigService.set` in a test (it writes config history rows and needs an actor).
3. **Errors are thrown inside `$transaction` callbacks, never returned** (§15.5 opening paragraph). Stop conditions use Nest exceptions with the exact Vietnamese texts of registry 4.13. Texts this part introduces (not pinned elsewhere) are listed per task and are author drafts.
4. **Post-commit work** (notifier calls, `WasteShipLockService.evaluateAndLock`) runs only after the transaction resolved, each wrapped in `try { … } catch (e) { this.logger.warn(…) }` so a failed message never fails the write (§10.2, R10.2.3, R10.2.4). Never call them on a replay. Unit tests prove the order (registry 4.10 post-commit order): the `$transaction` mock runs the callback, then pushes `'tx end'` to the shared `order: string[]`; notifier mocks push `'notify'` and `evaluateAndLock` pushes `'shipLock'`; a success case asserts `order.indexOf('tx end') < order.indexOf('notify')` (and the same for `'shipLock'` where it is called), a replay or failure case asserts `order` contains no `'notify'`.
5. **One `WasteEvent` per successful write, none on a replay** (§9, §11.1, registry 6). Events are written with `writeWasteEvent(tx, …)` inside the same transaction as the write, except `LOOKUP_MISS` (written with `this.prisma` before the 404 is thrown). Event meta (registry 4.5): every event except `LOOKUP_MISS` carries `meta.before` and `meta.after` (the changed fields only, `before: null` when the row did not exist) plus whichever of `subjectUserId` (the request's customer) and `staffUserId` apply; `LOOKUP_MISS` carries no before/after and sets the `pointId` column per registry 4.8.
6. **Advisory locks** only through `lockWasteStaffCap` / `lockWasteCustomer` from `wx/waste-locks.ts`. No `pg_advisory_xact_lock` text in any `rcv/` file (the `waste-locks.spec.ts` scan, registry 4.3). Row locks use ``tx.$queryRaw`SELECT "id" FROM "waste_requests" WHERE "id" = ${id} FOR UPDATE` `` (and the `users` / `game_profiles` / `waste_user_flags` equivalents named per task).
7. **Calendar time** only with `common/vn-time.ts` (`startOfVnDay`, `vnMonthKey`, `vnDateKey`); never `setHours` or `getMonth` (R15.1.93, R15.1.94); `wx/core/waste-caps.spec.ts` fails on either in any non-spec file of this part (waste source scans).
8. **Before modifying an existing file** run `grep -rln "<basename>" apps packages scripts --include="*.spec.*" --include="*.test.*" --include="*.mjs"` and fix every spec that would go red in the same task. The results known at plan time are written in each task.
9. **Raw SQL in unit tests** (registry 4.10 tagged-template reads): a test that inspects a `$queryRaw`/`$executeRaw` call reads it as `const [strings, ...values] = mock.calls[i] as [TemplateStringsArray, ...unknown[]]; const sql = strings.join('?');` and asserts on `sql` and `values`, never on `String(mock.calls[i][0])`. A fake `tx` whose raw-SQL mock is called while no `$transaction` callback is running throws `new Error('raw SQL outside $transaction')` (the `$transaction` mock sets an `inTx` flag around the callback).
10. **Unique violations.** Production code detects P2002 by duck typing, `typeof e === 'object' && e !== null && (e as { code?: unknown }).code === 'P2002'` (repo pattern `isUniqueViolation`, `api/modules/checkout/checkout.service.ts:850`), never with `instanceof Prisma.PrismaClientKnownRequestError`. A test that simulates it throws both a `new Prisma.PrismaClientKnownRequestError('dup', { code: 'P2002', clientVersion: 'x' })` and a plain `{ code: 'P2002' }`; both must take the same path. M3.4a and M3.4b write no unique column and catch no P2002.
